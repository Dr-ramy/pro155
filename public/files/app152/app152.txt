# المرحلة 3 — Image Manager

دي أهم وحدة في البداية.

المستخدم يضيف الصور:

```text
[ + إضافة صورة ]

┌─────────┐
│  صورة   │
│         │
└─────────┘
اسم الصورة
نوعها:
○ شخصية
○ مكان
○ وثيقة
○ حدث
○ خريطة
○ دليل بصري
```

بعد إضافة الصورة نخزن بياناتها في JSON.

مثلاً:

```js
{
    id: "img_001",
    src: "assets/images/person.jpg",
    type: "character",
    title: "الشخصية التاريخية",
    description: "",
    period: "",
    location: ""
}
```

**الهدف هنا:** الصورة لا تكون مجرد ملف، وإنما **عنصر تاريخي له معنى داخل النظام**.

# المرحلة 4 — Scene Engine

هنا يبدأ الـ Engine الحقيقي.

ننشئ Canvas باستخدام:

**HTML + CSS + JavaScript**

ولا نحتاج في البداية إلى Three.js أو WebGL.

كل عنصر داخل المشهد يكون Object.

مثلاً:

```js
{
    id: "character_01",
    type: "image",
    x: 320,
    y: 180,
    width: 180,
    height: 220,
    zIndex: 3
}
```

ونسمح بـ:

- Drag
- Resize
- Rotate
- Move
- Delete
- Duplicate
- Layer order

وبالتالي المعلم يستطيع تركيب المشهد بصريًا.

# المرحلة 7 — Historical Relationships

نبدأ في ربط العناصر.

مثلاً:

```text
الشخصية
    ↓
شارك في
    ↓
الحدث
    ↓
أدى إلى
    ↓
النتيجة
```

أو:

```text
الشخصية
     │
     ├── يعيش في → المكان
     │
     ├── شارك في → الحدث
     │
     ├── تأثر بـ → السبب
     │
     └── اتخذ → القرار
```

هذه العلاقات ستكون بيانات داخل JSON، وليس مجرد خطوط مرسومة.

# المرحلة 8 — Evidence Engine

ودي من أهم أجزاء البحث.

نحدد داخل الصورة **Hotspots**.

مثلاً:

```text
        ┌───────────────────────┐
        │                       │
        │       🖼 الصورة       │
        │                       │
        │          ● ← دليل     │
        │                       │
        │    ● ← دليل           │
        │                       │
        └───────────────────────┘
```

عندما يضغط الطالب على النقطة:

> **الدليل المرئي**

ثم تظهر:

- ماذا نلاحظ؟
- ماذا يعني؟
- ما علاقته بالحدث؟
- ما الاستنتاج الممكن؟

وهكذا تصبح الصورة **مصدرًا للتحليل**.

---

# المرحلة 9 — Emotion Layer

نضيف للشخصيات خصائص مرتبطة بالموقف:

```js
{
    character: "person_01",

    situation: "....",

    emotions: [
        "fear",
        "anxiety",
        "hope"
    ],

    evidence: "...",

    question: "كيف تعتقد أن الشخصية شعرت؟"
}
```

وعند عرض المشهد:

```text
👤 الشخصية

الموقف التاريخي

كيف تعتقد أنها تشعر؟

😟 قلق
😡 غضب
😢 حزن
😊 فرح

[ لماذا؟ ]
```

وبذلك لا تكون المشاعر مجرد Emoji، وإنما **مرتبطة بسياق تاريخي ودليل**.

---

# المرحلة 10 — Question Engine

ننشئ نظام أسئلة يمكن ربطه بأي عنصر.

أنواع الأسئلة:

### Observation

ماذا تلاحظ؟

### Identification

حدد العنصر التاريخي.

### Comparison

قارن بين صورتين.

### Cause

ما سبب الحدث؟

### Effect

ما النتيجة؟

### Inference

ماذا تستنتج؟

### Evidence

ما الدليل؟

### Emotion

ما شعور الشخصية؟

### Perspective

كيف يمكن أن تنظر شخصية أخرى للموقف؟

وهذا النظام سيكون قابلًا لإعادة الاستخدام في جميع الدروس.

---

# المرحلة 11 — Animation Engine

لا نريد فيديو تقليدي.

نريد **عرضًا بصريًا متحركًا**.

مثلاً:

```text
الصورة تظهر
     ↓
العنوان يظهر
     ↓
الشخصية تتحرك إلى المشهد
     ↓
Hotspot يظهر
     ↓
السهم يوضح العلاقة
     ↓
السؤال يظهر
```

باستخدام:

- CSS transitions
- CSS animations
- JavaScript timers
- Web Animations API

ولا نحتاج إلى مكتبة Animation خارجية في النسخة الأولى.

```js
{
    "lesson": {
        "id": "history_01",
        "title": "الدرس التاريخي",
        "period": "...."
    },

    "assets": [],

    "scenes": [],

    "timeline": [],

    "relationships": [],

    "evidence": [],

    "questions": [],

    "emotions": []

```

وده مهم جدًا لأن **المحتوى يصبح منفصلًا عن البرنامج**.

يعني نستطيع لاحقًا إنشاء 100 درس باستخدام نفس الـ Engine.

# المرحلة 15 — Moodle Integration

هنا لا نحول الـ Engine إلى Moodle.

بل العكس:

```text
              Moodle
                 │
        ┌────────┴────────┐
        │                 │
     Course            Student
        │                 │
        └────────┬────────┘
                 ↓
       Visual History Engine
                 ↓
          Interactive Scene
```

يمكن تضمينه لاحقًا كـ:

- HTML Activity
- iframe
- H5P/HTML package
- أو Moodle plugin إذا أردنا تكاملًا أعمق.

والنسخة الأولى لا تحتاج Plugin خاص.

# المرحلة 16 — تتبع التفاعل

لو أردنا أن يخدم البحث بصورة قوية، نسجل:

```text
Student
   ↓
Scene
   ↓
Image clicked
   ↓
Evidence opened
   ↓
Question answered
   ↓
Emotion selected
   ↓
Reason provided
```

مثلاً:

```js
{
    student: "anonymous",
    scene: "scene_01",
    interactions: [
        {
            type: "evidence_click",
            target: "evidence_03"
        },
        {
            type: "question_answer",
            question: "q_04",
            answer: "..."
        }
    ]
}
```

وهذه البيانات يمكن لاحقًا إرسالها إلى Moodle.

### والـ MVP الحقيقي الذي أنصح أن نبدأ به

يكون صغيرًا جدًا:

**ارفع 5 صور → صنّفها → اسحبها إلى المشهد → رتبها → أضف عنوانًا ووصفًا → أضف نقطة دليل → أضف سؤالًا → اضغط Preview → شاهد المشهد كطالب.**

إذا نجح هذا الجزء، فباقي الـ Engine يصبح **توسعة لنواة موجودة بالفعل**، وليس مشروعًا ضخمًا من البداية.

والميزة المهمة أن **HTML/CSS/JS + Bootstrap + Bootstrap Icons كافية جدًا لهذا الـ MVP**؛ لا نحتاج React أو Three.js أو Backend في أول نسخة.
